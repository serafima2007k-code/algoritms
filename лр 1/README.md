## Ход выполнения лабораторной работы

**Композиция**  
Связь: «состоит из», часть не может жить без целого.  
*Реализация:* поля-объекты, `unique_ptr`.  
*Жизненный цикл:* части создаются и уничтожаются вместе с целым.  
*Управление памятью:* целое отвечает за создание и удаление частей.

**Агрегация**  
Связь: «использует», часть может жить без целого.  
*Реализация:* указатели, ссылки.  
*Жизненный цикл:* части создаются независимо, живут дольше целого.  
*Управление памятью:* целое не отвечает за удаление частей.

**Статические члены**  
*Статическое поле:* одно для всех объектов, хранится в статической памяти.  
*Статический метод:* можно вызвать без объекта, нет доступа к нестатическим полям.  
*Применение:* счётчики объектов, общие данные для всех экземпляров.

## Контрольные вопросы

**1. Что такое композиция? Приведите пример.**  
Композиция – отношение "часть-целое", где части не могут существовать без целого. Целое создаёт и уничтожает части. Пример: Дом → Комнаты. Если дом снести, комнаты исчезнут.

```cpp
class Room { };
class House {
    vector<Room> rooms; // композиция
};
```

**2. Что такое агрегация? Чем она отличается от композиции? **
Агрегация – отношение "часть-целое", где части могут существовать независимо от целого.

**Отличия:**
* **Композиция:** части умирают с целым, создаются целым.
* **Агрегация:** части живут без целого, создаются отдельно.

**3. Как реализовать композицию в С++?**
Способы:

1. Поле-объект:
```cpp
class Car { Engine engine; };
```

2. Динамическая память:
```cpp
class Car {
    Engine* engine;
public:
    Car() : engine(new Engine()) { }
    ~Car() { delete engine; }
};
```

3. Умные указатели:
```cpp
class Car {
    unique_ptr<Engine> engine;
public:
    Car() : engine(make_unique<Engine>()) { }
};
```

**4. Как реализовать агрегацию в С++?**
```cpp
class Book { };
class Library {
    vector<Book*> books; // указатели
public:
    void addBook(Book* b) { books.push_back(b); }
    // В деструкторе книги НЕ удаляем!
};
```

**5. В чём разница времени жизни частей при композиции и агрегации?**
Композиция: Создание внутри целого, жизнь вместе с целым, удаление вместе с целым.

Агрегация: Создание снаружи, жизнь независимо, удаление не происходит (целое не отвечает за это).

**6. Что такое статическое поле?**
Статическое поле – принадлежит классу, а не объекту. Существует в единственном экземпляре для всех объектов.

**7. Как объявить и определить статическое поле?**
Объявление (в классе):

```cpp
class MyClass { static int count; };
Определение (вне класса):

int MyClass::count = 0;
Хранится в статической области памяти. Отличие от обычного: обычное поле – своё у каждого объекта, статическое – одно на все объекты.
```

**8. Что такое статический метод?**
Статический метод – вызывается без создания объекта: ClassName::method(). Нельзя обращаться к нестатическим полям (нет this).

**9. Для чего используются статические счётчики?**
Подсчёт количества объектов.
Управление ресурсами.
Генерация уникальных ID.
Сбор статистики.

**10. Что такое Singleton?**
Singleton – паттерн, гарантирующий, что у класса есть только один экземпляр. Реализация: приватный конструктор + статический метод getInstance().

```cpp
class Singleton {
    static Singleton* instance;
    Singleton() { }
public:
    static Singleton* getInstance() {
        if (!instance) instance = new Singleton();
        return instance;
    }
};
```

**11. Как запретить создание копий объекта (конструктор копирования)?**
```cpp
class MyClass {
public:
    MyClass(const MyClass&) = delete;
    MyClass& operator=(const MyClass&) = delete;
};
```

**12. В каком порядке вызываются конструкторы и деструкторы при композиции?**
Конструкторы: сначала поля-объекты (по порядку объявления), затем тело конструктора.

Деструкторы: сначала тело деструктора, затем поля-объекты (в обратном порядке).

**13. Можно ли изменить статическое поле из обычного метода?**
Да, обычный метод имеет доступ ко всем полям класса, включая статические.
```cpp
void method() { counter++; } // можно
```

**14. Почему статические поля определяют вне класса?**
Чтобы выделить память один раз.
Чтобы избежать множественного определения.
Для инициализации в одном месте.

**15. В каких случаях стоит использовать композицию, а в каких - агрегацию?**
Композиция: часть не может жить без целого (Дом → комнаты, Автомобиль → двигатель). Удаление целого → удаление частей.

Агрегация: часть может существовать независимо (Библиотека → книги, Корзина → товары).
